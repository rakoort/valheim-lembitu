### INTERACTION / security exposure: Infinity Hammer + InfinityHammerAddon + Server devcommands + World Edit Commands

Primary-source install scope: admin client for Infinity Hammer and World Edit Commands; Server devcommands admin client and optionally server (`R/JereKuusela__Infinity_Hammer.md:10-12`, `R/JereKuusela__World_Edit_Commands.md:8-12`, `R/JereKuusela__Server_devcommands.md:8-12`). Addon 1.0.1 is editing-client-only and says permissions apply, targeted at Valheim 1.0.12 (`R/sighsorry__InfinityHammerAddon.md:8-10`). The brief's game context must therefore not assume 1.0.7 compatibility.

**Can normal players use them?** Yes, selected powers can be delegated; not automatically full devcommands for all players. Infinity Hammer feature access goes through `PermissionManager.Instance.IsFeatureEnabledByHash("infinityhammer",...)`, not just local config (`D/Infinity_Hammer/InfinityHammer.dll.full.cs:11766-11798,11968-11974`). Server devcommands permission resolution supports explicit No/Force/Yes; absent permission falls back to local value AND `CanCheat`; CanCheat requires admin+devcommands on clients (`D/Server_devcommands/ServerDevcommands.dll.full.cs:10281-10289,10366-10374`). Permission entries can even override admin yes/no (`10309-10323`). Ordinary non-cheat commands remain available; explicit local command allow lists exist (`10401-10424`).

**What actually does the server check?** `ZNet.RPC_RemoteCommand` resolves the socket hostname plus server-known character ZDO; rejects missing peer/ZDO, then evaluates permissions (`7290-7329`). Remote calls require IsAdmin before allow-list matching (`10412-10424`), so granting only a command does not grant arbitrary remote-server command execution. This is real remote-command authorization, not a universal anti-cheat proof: feature gates also execute locally in clients. Installing these packages is not equivalent to validating every client-owned terrain/inventory mutation.

**Decision:** Keep as a separate trusted-admin maintenance profile; do not distribute to ordinary players. Install Server devcommands on the server only if needed for authorized remote operations, keep adminlist minimal and do not grant wildcard features/admin yes to guild members. No handshake requirement was established for the admin quartet; absence is expected. They are not world content requirements, but spawned objects, destructive edits, changed piece durability and terrain persist after removal. Keep InfinityHammerAddon with its required dependency versions (IH 1.84.0+, WEC 1.77.0+, SDC 1.113.0+) only for editing admins. Important IH keys: `No cost`, `Ignore wards`, `Ignore no build`, `Allow in dungeons`, `Remove anything`, `Repair anything`, health/invulnerability/physics overrides and tools; code properties above establish gates. Permissions are more important than distributing a benign client config. No ordinary-player runtime penetration test was run.

## 3. Repair and progression

Config has `XP per repair` at 4589, but no repair Harmony hook was found in this assembly; **do not claim that Comfy bypasses a verified Blacksmithing repair XP patch**. **Decision:** Cut ComfyAutoRepair under the literal client-gameplay rule. Keep vanilla repair and the established gear/progression systems; no permanent content lost by cutting auto-repair. If owner makes a repair-convenience exception, the >4 station-level clamp and direct-write path are concrete acceptance checks, not a proven EpicLoot crash. Align Blacksmithing `Enable durability bonus`, `Enable damage bonus`, `Enable armor bonus`, `Enable station level bonus`, `Skill gain factor`, `Skill effect factor`, ore/extra-output chances, smelting/kiln-speed bonuses and caps against EpicLoot and Guilds workshop upgrade (code:4570-4608). Recommend avoid multiplicative stat stacking by disabling Blacksmithing damage/armor bonuses if EpicLoot is intended to own gear power; retain crafting/smelting progression only with deliberate economic multipliers. Blacksmithing actual ConfigSync sets ModRequired=true, minimum1.2.4 (`code:4338-4344`), both sides; enhanced item data is character/world-item permanent [INFERENCE].
