## friendly_neighbor/ExperienceSystem 0.5.0 — REJECT

### Level / attributes / talents and axis ownership
Independent character XP to level 100 with automatic HP/stamina/regen/status-duration growth and a spendable 25-perk catalogue, rather than separate attribute allocation and a constrained talent tree (Prior:25-28; E:4921-4942). Existing prior research establishes 408 spendable points at the stock full catalogue budget. Configurable rank/cost/bonus per perk exists, but no per-perk Enabled and MaxRank is bounded **1–100** and additionally clamped to at least 1 in the accessor (E:2769-2771,7951-7957). It therefore cannot simply hide/remove unwanted perks through zero rank. Total point economy follows catalogue total cost, not a straightforward independent points-per-level knob (E:3939-3955). [INFERENCE] Full eventual catalogue completion undermines lasting soft specialisation unless deliberately retuned.

Overlaps EpicLoot damage/crit/resistance, MagicPlugin elemental combat, ImpactfulSkills training, Herbalist/Blacksmithing practice efficiency, ExpertExplorer exploration, and multiple regen/food owners (Prior:34-38,61-64). Zero bonuses can neutralise ordinary numeric perks; special Second Life is different. Own XP HUD and I/gamepad map-hold panel collide with other XP displays/input (E:7911-7916; Prior:88-90). No demonstrated hard conflict with BetterArchery, AzuExtendedPlayerInventory, Dive_In or SkadiNet; their full runtime interaction is unknown, not proven safe.

### Filled gaps: Second Life, reactions, respec
- **No meaningful respec-cost configuration**. Refund removes one rank, returns its entire point cost, saves/applies derived stats; reset clears allocations free of charge (E:3617-3667). Only Second Life cooldown prevents refund of that rank; reset retains it while cooling down. This prevents cooldown laundering but is not an economic respec cost.
- **Second Life cannot be individually disabled** by a documented config switch. Death prefix checks mod Enabled, rank and cooldown; successful activation restores at least 1 HP and returns false, cancelling Player.OnDeath (E:4594-4621). `PerRank` explicitly does not control revival; it is reserved, and MaxRank cannot be zero (E:7955;2769). High cost/cooldown is not disabling it.
- **Reactions affecting players CAN be disabled** with `01 General/ReactionsAffectPlayers=false`: target-hit guard and propagated-target filtering explicitly skip players (E:7104-7107,7576-7580); freeze also checks it (E:7506-7510).
- **Entire reaction system CAN be disabled**, but the `01 General/Enabled` description is misleadingly narrow: its same switch also gates Second Life, the death-XP penalty, activity awards, UI and normal stat bonus processing (E:7891,4577-4580,4598-4601,4331-4335; prior findings). Turning it off is not a useful clean 'leveling without reactions/Second Life' cutover. Turning each element off instead suppresses aura/reaction participation (E:8033-8036) without pretending to disable Second Life.

### Nearby shared XP: exact formula / authority
Killer receives base award X; **each** other player inside radius of the killer gets `floor(float(X) * Fraction)` (E:4286-4316; killer award/sharing E:4210-4213). Defaults radius 60 m, Fraction 1, enabled true (E:7941-7943). No party roster/invite/guild filtering; no division by recipients; no 8-player cap or map positions. Pre-personal-bonus total for N recipients is `X + (N-1)*floor(X*f)`, approximately `X[1+(N-1)f]`. At eight and default f this is 8X, not 1.10–1.25X. [INFERENCE arithmetic] Eight-person target would require f approximately 0.0143–0.0357, and that would under-reward two-person groups; a fixed fraction cannot implement the target across varying sizes. Existing insight/XP bonuses modify each player's final amount separately. Local player computes/stores progression; remote XP delivered through network (E:4304-4316); prior Jotunn config admin synchronization and EveryoneMustHaveMod/Minor strictness documented at Prior:173. Live enforcement/security was not exercised.

### Death / WAP
Death XP transpiler inserts after HardDeath, preserves bool result, warns if call count differs from one; loses current-level XP on a hard death (E:4542-4582). It does not replace native LowerAllSkills, so ordinary deaths can reach WAP's floor; **Second Life cancels the death entirely**, violating corpse run/skill drain/debuff requirements. WAP target evidence is `/tmp/lembitu-research/ProgressionCluster/VentureValheim.Progression.cs:3187-3219`. No bespoke timed death debuff observed. XP curve uses BaseXpPerLevel, LevelExponent, GlobalXpMultiplier and many source multipliers (E:7920-7938); month-long pace is tuneable in principle, not demonstrated.

### Code quality / persistence
Character customData uses invariant XP/fraction/ranks; v2 migration backs up original keys, rejects NaN/infinite fraction and reconciles overspend (E:3749-3820). Null guards and own-save hooks are present (E:4897-4918). Death transpiler matches semantic call and logs mismatch rather than relying on a fixed index, a positive. However mismatch merely logs and may silently lose intended penalty. Prior analysis covers per-frame reaction/HUD behavior; bounded aura refresh shown E:219-224, and UI gating/throttling E:849-852. Same core-stat patch layering with EpicLoot and magic/profession mods is an axis conflict, not established startup failure. Static screen clean. No live corruption or server-authority proof.

### Concept verdict
Satisfies configurable XP pace and independent persistent character progression; partially supplies perks, not the requested independent level-attribute plus limited-tree split. Violates meaningful-cost respec and uncancellable death. Nearby XP is not an intentional party. Reactions can exclude players but death-cancellation cannot be removed independently. **REJECT: inseparable Second Life and free respec are decisive**, despite comparatively careful save handling.

## Lorska/Valheim_Level_System_by_Lorska 0.99.9 — REJECT for this pinned stack

### Version / progression / concept coverage
Package label is 0.99.9 but BepInPlugin binary identifies **0.9.9.8**, with save schema 0.9.9.8 (L:1991-1994,794-798). Report both; do not normalize away this discrepancy.

Closest structural match in this slice: actual health/stamina/eitr attribute allocation plus separate stat points, selected mastery, specialisation and special-skill slots (LR:17-66). Defaults code: 1 attribute point/level, 2 skill points/level, 5 attribute points/boss, max level 80; all admin config (L:2850-2895). It also credits earlier bosses when a later one is killed (LR:34; L:1940-1967). [INFERENCE] That character-local bonus progression is not WAP personal-key granting, but adds its own boss progression economy, so boss-pillar overlap needs deliberate rejection/retuning.

XP curve recurrence `(previous requirement + BaseExpPerLevel)*ExpMultiplierPerLevel`, global/work rates, per-star/boss rates are configurable (L:2810-2834,2906-2909). Supports costly respec: above MaxLevelResetFree and unless ResetFree, loses `ceil((level-threshold)/10)` levels, clamped to minimum; reset clears attributes/mastery/specialisation/special skills (L:3436-3477). **README says free until 30; binary default is 20** (LR:26 versus L:2934-2941). Code below threshold calls free reset without visibly clearing current-level XP, another discrepancy with README's 'except accumulated XP' claim (L:3446-3448).

### Shared XP and parties
Nearby sharing is automatic, not invitation-only. Config range defaults 100 and `OnlyGiveExpIfDamageComesFromPlayer` can restrict XP to killer (L:2798-2804). Creature reward multiplies base table, stars, global rate and boss/miniboss factors; **ordinary kill amount divides by max(nearby XZ player count, indirect-kill divisor)**; bosses bypass division entirely (L:1970-1988). Thus ordinary fully eligible direct-kill groups approximate X total, bosses N*X, before personal gains/rounding. No configurable modest party-total multiplier or party-aware denominator in that path. No map-position party feature observed. Soft Groups dependency is legacy Smoothbrain/Groups, not Northarun/Guilds (L:1992). [INFERENCE] A fixed global XP rate cannot correct the ordinary/boss asymmetry while maintaining solo reference.

### Death / axis overlap
Normal death adds XP-loss postfix; loss is percentage of current-level requirement clamped to current XP (L:1036-1048,3235-3247), leaving vanilla skill-loss machinery available to WAP. However **Survivor intercepts lethal SetHealth**, consumes guardian power and restores health/stamina/adrenaline instead of dying (L:5180-5200,4490-4505); violates required deaths and couples to ProgressivePowers' axis. Special-skill factory exposes effect floats and localization, not an Enabled bit (L:3714-3749). Setting Restoration=0 [INFERENCE] may allow normal death, but still runs the special power side effects; this is not a verified clean disable. Special effects also modify power cooldown/healing/shields (L:2462-2468).

Clear gear-axis invasion: ItemData armour multiplier (L:4999-5003), physical-damage mastery, mobility/regen, magic enhancements and work/food bonuses (LR:41-54). Trophy bonuses can be disabled (L:2794-2797); almost every numeric effect is configurable (LR:87; L:3725-3731). Numeric zeroing is not generally equivalent to disabling branches, as Survivor illustrates. [INFERENCE] EpicLoot damage/armour/resistances, AdditiveDamageModifier, MagicPlugin, ProgressivePowers, ImpactfulSkills, Herbalist, BlacksmithingExpanded and ExpertExplorer would stack or compete on these axes. No established hard conflict with BetterArchery, DetailedLevels, AzuExtendedPlayerInventory, Dive_In, SkadiNet; separate O character window rather than vanilla skills replacement (LR:74-83) reduces the specific DetailedLevels dialog collision. O/P/L are configurable but L can overlap pack commands.

### Configuration / authority / quality
Jotunn admin-only config is used and configuration-sync callback registered (L:2318-2323,2790-2808). Compatibility bytes **2,3** mean EveryoneMustHaveMod/Patch (LI:12036-12038; enum definitions `/tmp/lembitu-research/ProgressionCluster/CompatibilityLevel.cs:22-25`, `VersionStrictness.cs:21-24`). Required mod/config model meets pack bar at source level; not demonstrated live. Level gains and allocation act on Player.m_localPlayer/save manager rather than server-owned character database (L:1053-1058,810-815); trusted pack, not anti-cheat authority.

Code has genuine rough edges:
- Packed pipe-delimited `m_knownTexts["VLS-Savedata"]`; each read repeatedly splits full save, find-index then parses string. Padding helps short rows, but malformed numeric fields use throwing Parse; migration rewrites and can force reset without backup here (L:794-855,1117,1141). [INFERENCE] Damaged/unknown schema can crash or lose allocations; no corrupt-save runtime exercised.
- Broad static local-player state; item/core-health patches affect shared combat formulas. `UpdateFood` transpiler injects after **any** `ldc.r4 0 / stloc` pair rather than a named calculation and has no expected-match assertion (L:5006-5032): fragile to game or other transpilers.
- Same Config section/key `BossExpMultiplier` accidentally binds both boss and miniboss entries (L:2818-2824). [INFERENCE] BepInEx reuses the existing entry, so intended independent knobs collapse.
- Empty catches in reset GUI cleanup hide failures (L:3478-3486). Input Update itself is straightforward guarded checks (L:2349-2385), but frequent save parsing inside stat effects is allocation-heavy [INFERENCE from readEntry design].

Static stale-reference screen clean; no proven startup failure. README warns crashes after 0.99.0 may require deleting config (LR:2); this is an author claim, not observed current-game failure. Version mismatch is concrete release hygiene evidence, not AI attribution.

### Concept verdict
Supplies the best level/attribute/talent-like split and meaningful level-cost respec here. XP curve configurable. But party model is wrong, boss XP exemption over-rewards groups, power/death/gear/profession/magic overlap is broad, and clean axis isolation is unproven. **REJECT for this pinned stack: invasive cross-axis effects plus fragile persistence/transpiler implementation.** It is not being cut for proven load failure; screen passed and runtime remains unknown.

## Ketanol/LevelingSystem_SharingXP 2.5.6 — POSSIBLE only as a heavily curated talent/perk catalogue; not a complete level/party fit

### Coverage / configuration
Independent total-XP level ladder with **one shared spendable skill-point economy**, including Vitality/Endurance/ArcaneCapacity and combat/utility/rare perks; no separate attribute-point authority or prerequisite talent tree in examined catalogue (K:7265-7302,2507-2523). README claims 35 skills (KR:15-20); compiled tuning list is consistent with an extended catalogue. Level cap, starting requirement, modifier formula, original level table, skill points per level, rested multiplier, per-star bonus and random spread admin config (K:7222-7239). Server synchronizes custom progression tables via own Jotunn RPC, ignores client-table packages, rebuilds/broadcasts from server with exception logging (K:7479-7517). Good pace configurability; one-month outcome unmeasured.

**Every skill has Enabled, MaxRank, BonusPerRank, BaseBonus, PointCost, admin-only** (K:7356-7368). Unlike ExperienceSystem, `SecondLife.Enabled=false` actually works because activation uses HasSkill, which checks Enabled (K:2552-2558,2570-2575). Can remove physical/elemental damage, every resistance, summon modifiers, FireFist, RemoteWorkbench/Stonecutter, XP gain, woodcutting/mining and flight individually (K:7268-7302). This is the strongest axis-isolation configuration in this slice.

Refunds are either allowed **for free** or blocked; rank-reset/removal has no item/XP/level cost (K:2531-2549,2592-2602,7238-7239). Does not meet meaningful-cost respec. Default I opens skill UI (K:7240), separate XP bar/shortcut local controls (K:7213-7219); visual collision with other level HUDs is [INFERENCE], not observed. DetailedLevels native skill dialog is not replaced in examined patches.

### Shared XP exact formula / authority
Creature **network owner**, not necessarily server, emits death rewards. Every alive player within 50 m of corpse receives full `round(tableXP*(1+stars*bonus))`, minimum 1; **no killer requirement, party/guild/invite filter, division or cap** (K:83-109). Player owner applies independently random spread, rested and ExperienceGain multiplier then updates total XP (K:468-477,521-540). For N otherwise identical eligible players default pre-bonus total is N*X; nearby radius configurable, **party multiplier/division not** (K:7232-7237). Radius zero is not a proper killer-only or party mode. RPC_AddExperience ignores sender identity and only checks positive reward/ownership (K:521-540); [INFERENCE] forged positive RPC can inflate client-owned XP. Not server-authoritative progression despite synced tables/settings. No party map positions.

### Death / WAP and other axes
Only found Player.OnDeath patch is SecondLife prefix returning false on activation (K:6217-6225). It restores full HP, records wall-clock cooldown, grants 3-second protection (K:2570-2582). Disable it explicitly. No level-XP death loss implementation/config found in the examined progression/patch/config surfaces (K:521-540,5941-6004,6217-6225,7222-7302); required character death penalty therefore missing. Ordinary death is not replaced when disabled, leaving WAP's native skill floor intact [INFERENCE patch composition, not runtime]. No timed respawn debuff added in examined paths.

Default PhysicalDamage/ElementalDamage, all resistances, crits reach EpicLoot/AdditiveDamageModifier axis; summon buffs and FireFist reach MagicPlugin; woodcut/mining/carry/XP efficiency overlap ImpactfulSkills/ExpertExplorer/profession stack; flight undermines traversal and RemoteWorkbench/Stonecutter bypass station requirement (K:6234-6273,7268-7302). Unlike other candidates these can actually be disabled. No boss-power economy found in catalogue. No hard conflict established with CreatureManager, ProgressivePowers, BetterArchery, DetailedLevels, AzuExtendedPlayerInventory, Dive_In or SkadiNet; entire stack runtime not verified.

### Code quality / save / compatibility
- New modular components and event subscriptions; data-load gating and owner checks prevent writes before character load (K:5982-6004;2677-2729). Save uses invariant `m_customData` keys and publishes ranks through ZDO; rank TryParse/clamp and legacy-name migration are robust improvements (K:2677-2729). Level XP saturates at int.MaxValue (K:537-538); custom table parsing logs errors and has fallbacks, rather than trusting JSON blindly (K:815-894;719-721). No backup copies observed for rank migration; malformed values normalize to zero [INFERENCE loss risk], not throw.
- Most core integration is postfix/additive prefix; no transpiler found in inspected patch catalogue. Remote-station perk temporarily mutates Piece.m_craftingStation and restores only in postfix, **not finalizer** (K:6234-6273); if original throws, shared prefab remains altered [INFERENCE]. Trophy chance mutation correctly restores in finalizer and preserves exception (K:6276-6317). Positive mixed patch hygiene, not uniformly safe.
- UI Update batches XP notifications, refreshes shortcut 0.25s and integrity 0.75s, avoids doing all work every frame (K:1178-1214). Flight/VFX adds substantial scope but can be disabled; no profiler run. Actual allocation/fps impact unknown.
- Admin-only attributes meet Jotunn-style lock model (K:7085-7088,7356-7368). EveryoneMustHaveMod/Patch decoded from KI:36483-36485. Static screen clean.
- README targets **Valheim 1.0.7 / BepInEx 5.4.2350 / Jotunn 2.29.2 / JsonDotNET 13.0.3**, not current brief versions (KR:23-38). Its bridge claims to patch only Jotunn 2.29.2, inactive on other versions; thus it should not rewrite 2.30.2 [INFERENCE unless live-exercised]. Author expressly says a full connected multiplayer session was not validated (KR:49-51), and did not reproduce a reported animal-invulnerability issue (KR:55-60). No claim that current build has that bug; no unsupported startup cut.

### Concept verdict
Configurable levels and spendable perks, excellent individual disable switches; WAP-compatible ordinary death path only with SecondLife off. Missing separate attribute budget, paid respec, level death XP penalty and invite-only modest-total party XP. **POSSIBLE as a curated perk component, not a turnkey solution**; Main should not treat it as meeting level/party acceptance without missing behavior being provided elsewhere. It is the top recommendation within this weak slice because meaningful isolation exists, not because download/popularity implies polish.
