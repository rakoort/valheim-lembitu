## 1. How many independent levels / XP economies?

**Three independent character-level XP ladders would run, not one integrated ladder:**

| Economy | Stored/provided progression | Relationship |
|---|---|---|
| WackyEpicMMOSystem 1.9.71 | Its own character XP/level and distributable attribute points; physical/magic damage, resource damage, HP/stamina/eitr, regeneration, damage reduction | Separate from vanilla Skills and the M2 Level skill. `R/EpicMMOSystem.cs:3637-3651,3721-3741,3794-3866,4462-4478`; repository config `config/enforced/WackyMole.EpicMMOSystem.cfg:38-57` |
| SkillsReworked 2.1.0 | New **Level skill**, kill XP, attribute points; attributes set the levels of mapped vanilla/modded skills; prestige/rebirth | Replaces skill-use advancement for mapped skills, not an EpicMMO extension. `M/M2Valheim__SkillsReworked.md:34-44`; `R/SkillsReworked.cs:4688-4713` |
| ExperienceSystem 0.5.0 | Independent level to 100, 408 spendable points for 25 skills; automatic HP/stamina/regen/status-duration growth plus critical hits/elemental reactions | Own saved character state and separate HUD, not an M2/EpicMMO bridge. `M/friendly_neighbor__ExperienceSystem.md:49-66,75-79`; `R/ExperienceSystem.cs:4897-4942,4980-5016` |

**TalentTree is not a fourth XP ladder:** hard-depends on SkillsReworked and derives 1 point/Level + 5 per defeated boss, with separate talent allocations. Rebirth/prestige reset talents; ordinary death Level loss leaves bought talents active and only restricts further spending. `M/M2Valheim__TalentTree.md:58-65`.

Other independent skill/mastery tracks still exist: vanilla per-skill practice XP; ImpactfulSkills Voyager, Hauling, Forging, Animal Whisper; Blacksmithing; Herbalist; ExpertExplorer exploration; ProgressivePowers per-boss kill mastery. None is an extra global character-level ladder. SkillsReworked can instead assign modded skills to attributes, eliminating their practice progression (`M/M2Valheim__SkillsReworked.md:35-38,52`). WAP is a floor/cap/drain authority, not an XP ladder. DetailedLevels is a readout/tracking mod, not XP progression (`docs/modstack.md:51`; `R/DetailedLevels.cs:143-153,2165-2168`).

## 2. Conflicts, overlaps and owner decisions

### P1 — OVERLAP / compounded progression: EpicMMO + ExperienceSystem + SkillsReworked/TalentTree

Evidence: all three character-level economies above; ExperienceSystem adds HP/stamina directly (`R/ExperienceSystem.cs:4921-4942`), whereas EpicMMO adds to food totals (`R/EpicMMOSystem.cs:3721-3728,3808-3845`). ExperienceSystem multiplies regeneration/skill-gain values (`R/ExperienceSystem.cs:4980-5016`); EpicMMO adds regen percentage to the same SEMan values (`R/EpicMMOSystem.cs:3731-3741,3794-3804,3871-3880`). EpicMMO multiplies item elemental damage and incoming physical/magic hit components (`:3745-3759,3817-3829,3849-3866`). There is **no sourced mutually-exclusive loader check** among these systems. They are not universally “all additive” or universally “all multiplicative”: flat maximum resources add, damage/regen reductions multiply at different stages, and prefix/postfix order can determine whether an added regen bonus is itself multiplied. [INFERENCE] This creates unmeasured compounding power, not proof of a crash.

Decision: choose one character-level authority. **Recommend keep EpicMMO, cut ExperienceSystem and SkillsReworked/TalentTree** for this pack: preserves the existing saved/pinned level economy, personal-key gear gates and tunable CreatureManager difficulty. If talent-build identity is preferred, replace EpicMMO with the M2 pair before the real run, rather than layer it on top; that alternative also requires the WAP skill-manager decision below and acceptance of TalentTree's fixed combat formulas. ExperienceSystem is not recommended as a third layer: its author explicitly says latest changes still need in-game/live multiplayer verification (`M/...ExperienceSystem.md:79`) and it introduces reactions affecting players (:62).

### P2 — HARD formula conflict: SkillsReworked versus WAP skill manager

WAP replaces `Skills.LowerAllSkills` and `Skills.Skill.Raise`, computes/clamps floor and ceiling, and zeroes accumulators (`R/VentureValheim.Progression.cs:3187-3239`). The currently pinned manager is enabled, floor is 10 per personal boss key, ceiling 100 (`config/enforced/com.orianaventure.mod.WorldAdvancementProgression.cfg:70-85`). SkillsReworked replaces `Skills.OnDeath`, manually lowers only unmapped skills and returns false (`R/SkillsReworked.cs:4640-4685`), and intercepts `Skills.RaiseSkill`, directly awards Level XP and prevents mapped skills advancing through vanilla Raise (`:4688-4725`). Therefore the native path through WAP's drain/gain hooks is **bypassed**, not combined as two consistent floor systems. The skill manager's “boss floors protect practice progression” semantics no longer apply to the M2-managed skills or Level death loss.

Decision: **do not combine these two skill authorities.** Keep WAP enabled with existing EpicMMO; if selecting M2, disable only WAP `EnableSkillManager`, retaining WAP private keys/recipe/action gates. Do not disable WAP wholesale. Exact effect of WAP clamps on M2 initial migration/attribute resynchronization is [INFERENCE] without game execution; bypass on the shown paths is observed code.

### P3 — HARD fighting formula / INTERACTION: TalentTree + EpicLoot + EpicLoot_ProgressionFix

TalentTree overwrites weapon `Skills.GetRandomSkillFactor` result and replaces `Skills.GetRandomSkillRange`, fixed `0.4 + 0.3 * factor` (`R/TalentTree.cs:20715-20750`). ELPF modifies EpicLoot's skill-range prefix to extend the **0.4 + 0.6 * factor** model above skill 100 (`F/skill-damage-range.cs:12-17,18-49`). These are competing authorities for the same damage roll, not merely two damage bonuses. TalentTree's constant result defeats ELPF's above-100 behavior for weapon hits; tooltip/range outcome depends on ordering of the two prefixes. No crash is claimed.

TalentTree scales armor to 65% in `Character.RPC_Damage` (`R/TalentTree.cs:19909-19938`). ELPF instead applies **full** player armor in a priority-first `Humanoid.BlockAttack` prefix and skips later resistance/armor steps (`F/block-after-armor.cs:20-48`). A blocked hit consequently bypasses TalentTree's intended 65% effective armor at the relocated mitigation step. Both mods also modify block/parry and projectiles (patch inventories in decompiled files). TalentTree documents no balance configuration (`M/M2Valheim__TalentTree.md:286-288`); decompile agrees its `SkillDamageNerfEnabled` is readonly true (`R/TalentTree.cs:14210`), not an editable escape hatch.

Decision: **cut TalentTree for the recommended EpicMMO/gear design**. If choosing M2, do not blindly add the broad ELPF patchset; choose which combat rules own random damage, armor/block order, resistance and bow behavior. “All install successfully” is insufficient.

### P4 — OVERLAP: ImpactfulSkills Forging + BlacksmithingExpanded + EpicLoot gear

ImpactfulSkills grants virtual station levels, persistent masterwork/weight bonuses and refinement changes (`R/ImpactfulSkills.cs:669-696`; README :150-164). BlacksmithingExpanded also increments `CraftingStation.GetLevel`, stamps persistent item bonuses and can improve damage/armor/elemental/block stats (`R/BlacksmithingExpanded.cs:3814-3857,3893-3907,4311-4324,4717-4775`). Both therefore do the smith-specialist job and change the gear curve; station-level postfix bonuses can sum [INFERENCE], while saved item-stat interactions need live proof.

Decision: **keep Blacksmithing as the specialist craft economy; keep ImpactfulSkills only with `EnableForging=false`** (or choose the opposite, not both). With EpicLoot/EpicMMO supplying combat power, prefer Blacksmithing damage/armor/elemental/shield bonuses disabled or conservatively capped; retain durability, smelting economy and specialty identity. Exact relevant config names are in the per-mod table. This is tuning advice, not a measured balance prescription.

### P5 — INTERACTION: ImpactfulSkills, WAP floors, practice skills, XP boosters

ImpactfulSkills adds a `Skills.RaiseSkill` knowledge-sharing prefix (`R/ImpactfulSkills.cs:1523-1526,7185-7247`) and numerous training events, including cooking streak/eating (`:704-710`); Herbalist also prefixes/postfixes `Skills.RaiseSkill` (`R/Herbalist.cs:2286-2300`). EpicLoot patches RaiseSkill for its effects (`R/EpicLoot.cs:28766-28769`) and GetSkillFactor (`:30228-30231`). ExperienceSystem multiplies `SEMan.ModifyRaiseSkill` (:5000-5006). WAP boss floor unlocks milestones earlier than use-only training; it is intentional catch-up, but it can instantly qualify an otherwise-new skill for AoE/farming/station perks.

Decision: choose XP/catch-up pace consciously. Recommended **keep WAP floor, modest utility perks, disable redundant ImpactfulSkills Forging and initially `EnableKnowledgeSharing=false`** so practice-rate boosts do not silently multiply; do not adopt ExperienceSystem's extra skill-gain booster. Configure perk thresholds against boss floors, not only vanilla grind speed.

### P6 — INTERACTION / OVERLAP: AdditiveDamageModifier, EpicLoot resistances, CreatureManager and TalentTree

ADM replaces `HitData.DamageModifiers.ApplyIfBetter` and all `HitData.ApplyResistance` processing (`R/AdditiveDamageModifier.cs:1536-1567`), so base equipment/mead/status resistance contributions add rather than vanilla strongest-priority selection. README defaults resistant -30%, very resistant -45%, immune -100%, players' capped types retain 10% damage (`M/sighsorry__AdditiveDamageModifier.md:40-48,71-87`). CreatureManager has an armor-piercing `Player.GetBodyArmor` hook (`R/CreatureManager.cs:9289-9300`) and separate received/outgoing damage modifiers in its YAML (repository `config/enforced/CreatureManager/levels.yml:55-86`, karma equivalents). **ADM's player floor applies to resistance processing, not every subsequent or preceding MMO/CreatureManager/EpicLoot mitigation multiplier.** It is not a final guarantee that players take 10% of original damage after all systems.

TalentTree “Even Ground” manipulates vanilla resistance enum tiers (`R/TalentTree.cs:6282-6322`) whereas ADM encodes/composes custom additive totals; [INFERENCE] the enum-specific talent will not interpret all ADM custom combined modifiers correctly. This needs a live target-specific test if those mods are selected together. No evidence that ADM and CreatureManager are globally mutually exclusive.

Decision: **keep ADM only if owner explicitly wants additive resistance semantics and measures representative EpicLoot/CreatureManager builds**; set player minimum keys, tier percentages, fall behavior deliberately. Recommended keep (with M2 cut) as a resistance policy, not another progression ladder, and do not promise its floor prevents immunity from the whole stack.

### P7 — OVERLAP / INTERACTION: BetterArchery, TalentTree, EpicLoot projectile effects

Both BetterArchery and TalentTree patch `Projectile.Setup`, `Projectile.OnHit`, `Attack.FireProjectileBurst`, `GameCamera.UpdateCamera`; both provide zoom/draw/movement/arrow behavior (`R/BetterArchery.cs:3440-3464,3677-3809`; `R/TalentTree.cs:10573-11028`). BetterArchery config has arrow velocity/gravity, zoom, cancel, movement slowdown and retrievable arrows (`:650-674`). TalentTree Hunter duplicates zoom, projectile velocity, multiple shots, ammo economy and draw auto-release (`M/M2Valheim__TalentTree.md:145-159`). EpicLoot adds its own quick-draw/multiple-projectile effects; ELPF also fixes bow release/ammo damage/multi-shot.

Decision: recommended **keep BetterArchery, cut TalentTree**, avoid multiplying all arrow-effect authorities. If M2 chosen, disable BetterArchery zoom and movement/draw modifications and consider retaining only quiver/retrieval. Current proof is overlapping targets/functions, not a demonstrated crash. Unload quiver contents before disabling: the config warns arrows are lost (`R/BetterArchery.cs:636`).

### P8 — OVERLAP / INTERACTION: ProgressivePowers versus TalentTree Guardian Power talents; WAP key gates

ProgressivePowers defaults `Block Power Activation=true` and adds attuned passive powers, max attunements and per-boss kill mastery (`R/ProgressivePowers.cs:258-275,2225-2253,2374-2420`). TalentTree Divine Favor reduces power cooldown and cycles unlocked powers (`M/M2Valheim__TalentTree.md:191`; `R/TalentTree.cs:6981-7086`). Cooldown talents lose purpose when activation is blocked; each independently owns selection/activation. ProgressivePowers kill-credit range defaults 200m (:259), while WAP personal-key award is tied to a 100m vicinity of chunk host (`CONTEXT.md:92-96`). This is not the same presence predicate, even if configured radii match.

Decision: **keep ProgressivePowers, one attunement, keep WAP power gate, cut TalentTree**. Align kill-credit expectations/range with personal-key policy; matching numeric radii alone is not verified equivalence. PP is kill/mastery progression, not a second character XP level.

### P9 — OVERLAP / UI risk: DetailedLevels versus SkillsReworked; multiple HUD XP bars

SkillsReworked rewrites `SkillsDialog.Setup`, `GetSkillList`, update/controller selection and has an XP bar beneath health (`R/SkillsReworked.cs:4034-4044,4175-4365`; README :20,28). DetailedLevels modifies that same dialog/list (`R/DetailedLevels.cs:1742-1748,2112-2118,2429-2580`) and assumes `SkillsFrame/Closebutton` layout (:1781-1841). [INFERENCE] rewritten list/layout can conflict; no runtime crash observed. ExperienceSystem adds another HUD experience bar and default I/gamepad Map hold (`M/...ExperienceSystem.md:64-66`; `R/ExperienceSystem.cs:7911-7915`). TalentTree hotkeys Q/G/LeftShift (`R/TalentTree.cs:15992-16000`) overlap vanilla/autorrun/guardian/sprint functions; BetterArchery Mouse1/E/Alt-number bindings (`:646-663`) need auditing against other pack actions. Pixel overlap is [INFERENCE], not visually tested.

Decision: recommended **keep DetailedLevels with vanilla practice skills and only EpicMMO's XP bar; cut the extra XP HUD systems**. If choosing M2, cut DetailedLevels or prove rewritten skills-window operation before retaining. Preserve requested vanilla health/stamina display using EpicMMO client UI palette (exact keys need owner pack review; see gaps).

### P10 — OVERLAP, not proven incompatibility: MagicRevamp vs MagicPlugin

README calls Revamp an alternative and requires Smoothbrain Backpacks (`M/blacks7ar__MagicRevamp.md:4,8,21-36`), despite manifest listing only BepInEx (:3). **Binary confirms hard BepInEx dependency `org.bepinex.plugins.backpacks`**, flag 1; MagicPlugin is soft dependency flag 2 (`R/MagicRevamp.il:1172-1179`). AdventureBackpacks is not this plugin ID [INFERENCE until its GUID is checked], so installing the existing similarly-named backpack does not establish satisfaction.

The mods deliberately share the **BMR armor identities**, e.g. Tattered/Sorcerer/Warlock/PolarWolf/Seeker/Crimson (`R/MagicPlugin.cs:3862-4362`; `R/MagicRevamp.cs:4183-4243` and later armor registrations). **Revamp detects MagicPlugin and skips its armor registrations/effects**, not an unavoidable duplicate-prefab crash (`R/MagicRevamp.cs:2164-2172,3082-3089,3168-3171`). Revamp adds `BMR_SpellTable`, `BMR_BookShelf`, `BMR_MagicCrystal`, `BMR_SpellBook` (:3174-3218); distinct biome staffs/wands and spell ammunition coexist functionally with MagicPlugin's BMP staffs/tomes/totems/accessories. Both patch attack start, damage/status effects and resource totals; a live combined balance result is unknown.

Decision: **keep existing MagicPlugin, cut MagicRevamp** unless deliberately replacing the magic design with spell-ammunition/vanilla-biome progression. If replacing, install the actual Backpacks dependency and preserve/migrate existing BMR armor plus BMP items/stations safely before removal. Coexistence is supported in one narrow armor path, not proof that two magic economies are desirable.

### P11 — HARD initialization conflict: ELPF 0.1.153 vs current AzuCraftyBoxes 1.8.19

Current repository pin remains AzuCraftyBoxes 1.8.19 (`docs/modstack.md:46,158`). ELPF declares optional integration exact version **1.8.27** (`F/plugin.cs:35-36`); `TryGetExact` throws on installed mismatching version (:51-55); `CraftyBoxesUnload.Initialize` calls it (`F/crafty-boxes-unload.cs:17-25`). This is invoked in the main gameplay initialization (:227). Catch unpatches **all main ELPF gameplay patches**, Ready=false, reports startup error (`F/plugin.cs:254-257,272-285`). There is no integration-disable config switch. Older AzuCraftyBoxes is not treated as “integration skipped”. Other exact optional integrations similarly require their pinned versions if installed (:15-48), including DiscordConnector 3.1.3 (matches this stack).

Decision: **do not deploy ELPF with current AzuCraftyBoxes pin**. Recommended cut ELPF pending an intentional decision to adopt its whole patchset and update compatible dependencies; if owner wants it, exact compatibility change is mandatory. Its protection/migration patches are initialized in separate Harmony instances and may remain even after main gameplay rollback (:139-165), so failed initialization is not identical to total absence.

It automatically initializes many integrations and applies every HarmonyPatch class (`F/plugin.cs:172-250`). Most side behaviors **have no independent off switch**.

### WAP PlayerMustKnowRecipe gating

Current recipe mode remains `PlayerMustKnowRecipe` (`config/enforced/randyknapp.mods.epicloot.cfg:28`; docs/modstack.md:41), specifically because world keys are blocked. ELPF's new equipment candidate/crafting-history gate is guarded by **PlayerMustHaveCraftedItem** (`F/eligibility.cs:15,81-101`; `F/crafting-history.cs:216-218`), not an unconditional replacement of recipe mode. **No demonstrated hard conflict with WAP recipe/private-key gating in the current mode.** ELPF doesn't make crafting history active just because installed. If switching modes, owner changes gate from recipe-known to actually-crafted, and guaranteed boss/bounty fallback can award a Club when nothing is crafting-eligible (`F/eligibility.cs:92-97`). That fallback does not unlock recipes. Recommend retain PlayerMustKnowRecipe; do not change to global-boss unlock modes. Other ELPF core code continues to apply even with recipe mode; the mode guard is not a master off switch.

### Preloader follow-up

Binary decompiled at `R/Preloader-verified.cs:43-102`, bundled source `F/patchers/discord-connector-file-log.cs:17-63`. TargetDLLs empty; Patch no-op; Initialize subscribes to assembly load. On **DiscordConnector** load it Harmony-prefixes `DiscordConnector.Common.VdcLogger.LogToFileAsync(string,string)`; serialized synchronous append returns CompletedTask, avoiding sync-over-async Unity-continuation problem documented in source (:47-63). It does not patch EpicLoot on disk or inject a new progression model.

Main plugin does **not test for preloader presence** in startup (`F/plugin.cs:105-258`). Absence therefore does not explicitly abort ELPF progression initialization; [INFERENCE] it leaves DiscordConnector original logger's deadlock/race exposure rather than disables progression. The brief's server-container limitation (patchers not mirrored) means this advertised logger fix would not execute there. Actual startup deadlock without it is not reproduced. With DiscordConnector absent the preloader has no target. Source validates reflected logger fields/method and throws if changed (:25-30), so blindly using another DiscordConnector version is unsafe.

## 6. Recommended coherent keep/cut table

**Design recommendation:** one existing character-level economy (EpicMMO), one gear/enchantment authority (EpicLoot), one personal-key/floor authority (WAP), fixed difficulty authority (CreatureManager with no headcount), bounded specialist utility/practice progression. Avoid adopting a second whole combat rewrite to compensate a difficulty system already independently tunable.

| Mod | Recommended disposition | Why / split responsibilities |
|---|---|---|
| EpicMMO | KEEP | Existing tunable level/attribute curve; no creature-level ownership |
| ExperienceSystem | CUT | Third unrelated level/skill/tree/reaction economy, large automatic resource growth and unverified latest multiplayer |
| SkillsReworked | CUT | Replaces practice skill authority and bypasses WAP floor/drain; optional alternative **replacement**, not addition |
| TalentTree | CUT | Requires SR; fixed damage/armor/creature-armor rewrite; conflicts with ELPF mitigation order and overlaps powers/archery |
| EpicLoot | KEEP | Single gear/loot/enchant curve; personal recipe gating |
| EpicLoot_ProgressionFix | CUT FOR CURRENT STACK | Exact AzuCraftyBoxes incompatibility; broad always-on chat/block/loot/plant/inventory patchset needs explicit owner approval, not “fix” assumption |
| WAP skill manager | KEEP | Boss-key floor protects latecomers and specialty practice; retain relative loss |
| CreatureManager 1.2.5 | KEEP | Sole monster/boss difficulty, HP/DMG per player zero; fixed modifier/karma choices |
| ImpactfulSkills | KEEP, SPLIT / TUNE | Useful noncombat specialization; disable Forging when Blacksmithing owns craft skill, avoid accelerated shared knowledge initially, decide movement/farming/refinement privileges |
| BlacksmithingExpanded | KEEP, SPLIT / TUNE | Craft specialist economy; disable redundant/unbounded combat bonuses where gear/MMO already own power, deliberately coordinate BetterStations speed |
| Herbalist | KEEP, TUNE | Support specialization; set tonic gates/XP/heal strength, no separate global character-level ladder |
