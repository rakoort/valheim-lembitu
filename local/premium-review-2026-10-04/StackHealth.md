# StackHealth — upstream health and performance review

## Summary
1. **Upgrade Guilds 1.2.2 → 1.2.3 before launch:** the current pin can lose banner territory on reconnect/restart; upstream describes deterministic network-ID recovery.
2. **Azumatt is actively publishing on Hexium, not abandoning these six mods.** All six have newer releases there. AzuCraftyBoxes 1.8.27 contains dupe/item-consumption and large-chest-base fixes; AzuEPI 2.6.1 repairs AdventureBackpacks/cape/custom-slot faults. These are more consequential than catalogue deprecation itself.
3. **Expand World Size has two open high-impact reports:** swimming beyond the vanilla boundary and inability to reconnect there. No confirmed fix release was located; exercise the exact 13,250 m / 1.325 stretch world before freezing it.
4. **EpicLoot 0.14.13 already contains numerous dupe/item-loss corrections,** but open reports remain for Rested-based carrying capacity and socket hotkey interoperability. A closed issue is not sufficient evidence of a release fix; bounty migration is explicitly covered by 0.14.13.
5. **Hexium migration needs staging work and a redistribution/license decision.** Downloads are ordinary versioned ZIP URLs and were actually fetched without login, but stage-stack.sh hardcodes Thunderstore. ProximityVoiceChat 1.0.3 explicitly retracts the accidentally bundled MIT license.
6. **Best low-overlap performance trials:** Balrond Core Optimizer 0.2.1 in Conservative Mode; ValheimScalability 1.0.0 in Adaptive mode. Their shortlisted DLLs pass the repo stale-field screen, but neither is performance-proven on this pack.
7. **Do not stack a second network owner onto SkadiNet.** ValheimTune is promising measured work but overlaps ZDO pacing/synchronization and rewrites save behavior; SteadyFrame includes portal timing gameplay changes and claims Windows support only.
8. **BetterChat's Clan-specific cut reason expired, but Guilds still patches Chat.InputText.** The narrower prefix/transpiler overlap looks tractable rather than proven broken. MultiUserChest 0.6.2 explicitly supports 1.0, but its networked-item risk rationale remains valid.

## Sources, method and scope
Read-only audit of all 63 lock entries against the supplied full Thunderstore API snapshot `/tmp/lembitu-premium/thunderstore-valheim.json` (latest version/deprecation metadata) and `docs/modstack.lock.json:2-64`. Each linked package below owns its release metadata. Version-specific downloaded archives are retained under `/tmp/lembitu-premium/StackHealth/<Owner>-<Name>-<Version>/`; README/changelog are primary author-shipped evidence. Package API requests returned 429, and normal download endpoints returned 403; alternate CDN `https://gcdn.thunderstore.io/live/repository/packages/<Owner>-<Name>-<Version>.zip` succeeded. GitHub issues were fetched through owner repositories' REST API with state=all, sorted updated, first 100, and comments for material reports. This is bounded public evidence, not a Discord audit and not proof of absence of bugs. No game, server, build or tests run; only explicitly requested assembly screening and static decompilation.

All latest library versions are older than 1.0 only for JsonDotNET/YamlDotNet (game-agnostic libraries), and DiscordConnector 3.1.3 (2026-08-25). No other latest pin in this snapshot predates 2026-09-09. Release date is only a risk heuristic.
