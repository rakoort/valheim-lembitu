# AuditUX — current Pack UX, controls and onboarding

## Summary
1. **Fix B and H before adding UI mods.** B is both push-to-talk and Oathbound's spell selector/companion call; H casts/orders companions and also toggles AzuHoverStats. These are real simultaneous actions, not just reused keys in different menus.
2. **Building has a second collision cluster:** Extra Snaps Q/E competes with vanilla autorun/use/category tabs and PlanBuild Q; F4 also opens DetailedLevels. LeftAlt is dodge, snap mode, quick-slot modifier and inventory favourite modifier, though several consumers are context-gated.
3. **The Pack already supports client seeds.** `config/client/` overlays package seeds last; it currently contains only EpicLoot. No new distribution mechanism is needed for controls/layout. Keep gameplay permissions enforced on the server, not in these seeds.
4. **The first journey is under-explained.** Guild spawns are 0.5–1.2 km from the only Oathstone; the HUD says “Visit an Oathstone,” but does not tell a newcomer that kills earn no class XP until choosing an oath, or that Calling selection is a separate skills-window operation.
5. **Calling and ladder feedback are better than docs alone:** stars have contextual tooltips, quotas and destructive-change confirmation; ItemRequirement appends profession requirements to crafting descriptions. Missing is a concise overview linking these systems to boss keys, trade and party proximity.
6. **HUD congestion is primarily bottom-left/bottom-centre, not one giant top-right pile.** Oathbound attaches XP below health and ability text to its right; quick slots derive their default position from health; Guilds occupies bottom-centre. Clock is top-centre; voice icons are world-space; ValheimVisualEnhanced adds visual effects, not a persistent HUD bar.
7. **One enforced presentation choice deserves loosening:** AzuEPI server-locks quick-slot HUD visibility and empty-slot display. Let players hide unused presentation without altering slot count or gameplay. Most other restrictive settings examined directly serve the concept and should stay.
8. **Controller parity is incomplete.** Dive and XPortal use native controller actions, SocialSystem has block+Y, and AzuEPI extends hotbar navigation; Calling stars are mouse click targets and Oathbound only registers keyboard MainKey for its six actions. Do not advertise controller-ready onboarding without a controller Shakedown.

### Proposed conflict-free keyboard seed set
Keep vanilla controls intact. Conflict-free means distinct **global** actions, while retaining documented context-local mouse/interaction reuse; not a claim of tested runtime arbitration.

- Oathbound: keep H/B/J/K (class-specific H/B sharing intentional). Avoid modifier combinations: `Oathbound.cs:10676–10677,10720` sends MainKey into Jotunn; modifiers are not represented in these action definitions.
- PVC `[3 - Microphone] Push To Talk = Mouse3` (side mouse button), mute/deafen stay None. Keyboard-only alternative `RightAlt` is not in audited default set. Explain that fallback on the controls board.
- HoverStats `[1 - General] Disable All Visuals = Delete`.
- DodgeShortcut `[Mechanics] DodgeShortcut = Mouse4`; keyboard-only alternative `RightControl` is inventory-context reused by MouseTweaks but dodge excludes inventory.
- AzuEPI `[8 - Quick Slot Hotkeys] Hotkey 1 = Z`, `Hotkey 2 = U`, `Hotkey 3 = N`; set all three `Hotkey n Display Text` to blank so labels regenerate. These main keys are free in vanilla ZInput and scoped defaults, and eliminate Alt+sit/walk ambiguities. Keep unused 4–8 unbound in seed rather than pre-allocating unseen shortcuts.
- PlanBuild `[Keybindings] Blueprint Marketplace GUI toggle key = Insert`, `Toggle = Equals`, `Mirror = Minus`; `AltModifier = RightAlt` to avoid Extra Snaps LeftAlt. Keep Shift/Ctrl contextual tool modifiers.
- Extra Snaps `[Manual Snapping] Iterate Placing Piece Snap Points = LeftBracket`, `Iterate Targeted Piece Points = RightBracket`; keep LeftAlt/CapsLock/F3/F4. This stops Q/E stealing vanilla use/category/autorun and PlanBuild operations.
- DetailedLevels `[1 - General] HotKey = F8`.
- Keep Guilds F9, Marketplace F7, Social O/P, backpack I/Y/L, Clock Home, contextual Dive/XPortal/remote controls.
- Preserve controller contextual assignments initially. There is no honest config-only conflict-free controller set for Calling/Oathbound parity: add explicit focus/navigation support to Calling stars and controller action definitions to Oathbound or document keyboard/mouse requirement. Only Shakedown settles accessibility and input arbitration.

These are plain local or explicitly unsynced registrations. **Do not put control keys into `config/enforced/` expecting a server overlay to change players' controls.** Slot counts, private key locks, party limits, voice ranges, blueprint direct-build permissions remain server settings. Sync inspection evidence: AzuEPI `synchronizedSetting:false` above, PVC same; AdventureBackpacks UnsyncedConfig; Guilds/Marketplace `1 - Client` bind directly; PlanBuild key entries bind directly separately from Server Settings. Extra Snaps is local despite descriptive sync wording (`docs/modstack.md:90`).

Confidence: high for registered key values and overlapping consumers; medium for actual simultaneous dispatch/context; controller confidence limited by no live input. Shakedown required: hold PTT as Mage and Hunter; use each quickslot while moving; every snap/blueprint modifier with rune equipped; all controller UI openers; type H/B/O/P in chat and each custom input field.

- **Bottom-centre:** Guilds 420×30 at `(0.5,0)` anchor and Y=4 (`Guilds.cs:3151–3154,11209–11210`). - **Top-centre:** AzuClock `Clock Location String = 48%,0%`, and `Hide When Map Open = Off` (`AzuClock.cs:1417–1419`). Clock may stack over boss/event banners [INFERENCE], and remains on full map. - **Map/minimap:** BetterMap auto-pins plus Guilds guild positions/pins plus Social party positions can duplicate the same friend and clutter discovered areas. Confidence: high for anchor/layout defaults, medium-low for rendered overlap; all pixel-level claims remain Shakedown-only. Prefer repositioning/hiding redundant presentation before adopting a wholesale HUD replacement that patches Hud/InventoryGui/SkillsDialog on top of this stack.

## 5. Pack construction and seed safety
`build-client-pack.sh:48–51,165–185` stages adopted pins via stage-stack, removes server-only plugins and adds Lembitu plugins. It copies complete pinned BepInEx loader (`193–200`), reshapes staging beneath `BepInEx/` (`254–277`), then copies every repository `config/client/` seed last (`279–289`) and asserts they landed (`333–340`). Partial configs fill omitted registered values at first launch, according to builder contract (`279–282`). It emits zip, manifest and file hash inventory (`379–407,409–447`). This audit did not build a Pack.

**Yes: ship seeds, already supported and within Pack rule.** Keys/layout/presentation are preferences and may differ per client; combat/economy/access knobs must still be server-synced/locked. Seeds are not an enforcement mechanism. Keep seed files minimal, avoid credentials and device names/microphone IDs, and do not place whole copied config dumps with gameplay overrides there. Include actual shortcut display labels or leave auto-generated labels blank; otherwise new bindings show old Alt+X text.

Update/install caveat: builder copies whole seed files into archive, not merges into existing player files. Extracting a later Pack over an existing install can reset their remapped keys/layout/mic preferences if those files are included. The premium installation guide needs an explicit preserve/backup preference-config step or an installer merge policy; do not promise user preferences survive updates. Same Pack binaries remain intact while preferences are restored.

## Ranked proposals
1. **Adopt immediately:** client seed controls above, especially PVC B→Mouse3, HoverStats H→Delete and F4 split. Highest value, zero new mods, no difficulty effect. Confirm on fresh-profile Shakedown.
2. **Adopt before launch:** three replicated sign clusters and a concise in-game controls board; ensure no-oath player knows XP is inactive and how to find the Oathstone. This protects the first hours of a ~50–60 h Run.
3. **Try during Shakedown:** one eight-player HUD layout, 1080p and small-screen/controller variants; reflow/hide guild/empty-slot presentation before considering a HUD overhaul.
4. **Adopt:** QuickConnect hostname/text seed, blank password, and preference-preservation update guidance. Builder already supports it.
5. **Request upstream / implement narrowly if needed:** unsync AzuEPI visibility preferences; don't fake this by moving server-synced keys into a client seed. Controller-aware behaviour must stay usable.
6. **Do before claiming controller support:** Calling star navigation and Oathbound controller action bindings; current keyboard/mouse-only controls must be stated honestly meanwhile.
